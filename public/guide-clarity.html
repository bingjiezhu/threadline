Start with one first task.

cd Threadline
npm start

Open http://localhost:4173 and create an account. Use Node.js 22.16 or newer. Core management needs no dependency installation or AI key. Your workspace starts empty and your records persist after a full restart.

  1. Save a team note you have permission to use.
  2. In Knowledge map, confirm the original words, date, topic and colleague.
  3. In First task, write one goal and what a completed result looks like.
  4. Select Find my next steps. Check who is named, why, and what still needs checking.
  5. Choose your steps, confirm, and select Add to my tasks.

Your colleague is not messaged automatically. You report real progress. Checking off one step does not complete the whole goal.

See the original words and date.

Ask the person.

Choose a step.

Only your selected steps become tasks.

Illustrative scenario

The guide says Maya. Now Jordan handles it.

Alex wants to try the company test site. A test site, also called a sandbox, is a safe place to practice without changing the live app.

The old note names Maya. A later note says Jordan handles access. Alex checks the date and original words, then confirms the change. The old plan stops. Checking again shows Jordan and explains why. Training and access still need checking.

To rehearse in a separate temporary workspace:

npm run demo:clear

The terminal prints the address and a random practice password. Fictional notes are prepared; the later note is not yet confirmed as a replacement. Your normal database is not touched.

Use Update who to ask to review the later note, then Confirm the change. A later upload alone never changes responsibility.

Keep the boundary clear

Useful software. No invented results.

Where is the AI?

AI here means a language model that can help write the plan. The optional OpenAI adapter is implemented but was not called live in this release. The 42-second stage excerpt and original 122-second film use saved-note planning, labeled AI off. The final 150-second film adds an actual Gemini 3.8 Flash workflow on Vertex with explicit consent and fictional data. Code and user confirmation control sources, people and saved tasks.

Who provides the team notes?

The new employee and buddy can start with a few authorized notes. Important responsibility is explicitly confirmed by the workspace user. It is not a company-wide source of independently verified authority or an implemented manager approval role.

Is this better than search and a buddy?

That is the comparison to run. The proposed value is keeping a note, a person and a next step together, and stopping old guidance after a confirmed change. Count all preparation and correction effort. There are no measured savings or paying users in this release.

How do I keep my data?

Before upgrading, stop the server and back up the complete .data directory using the documented procedure. Schema 3 is unchanged. JSON export is readable, but core JSON restore does not reconstruct every first-task route, plan or chat binding. Use the full SQLite backup for complete restoration.

What was tested?

The final report separates automated checks, real-backend UI flows, clean startup and media validation. The October 18 readiness check passed 17 focused checks with native Google Chrome navigation on macOS, including a 390px mobile viewport. Earlier recordings used the documented renderer harness and real HTTP/SQLite. Public HTTPS, PowerPoint playback and real Slack installation remain separate acceptance checks.
