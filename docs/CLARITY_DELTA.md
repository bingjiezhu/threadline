# Clarity edition 1.3.2 — changes from 1.3.1

## Changed in this package

- Reworded the focused first-task page around **Who to ask / Why this person / What to do next**.
- Original quotations, dates, human confirmation, unknowns, stale-plan blocking and selected task creation remain intact.
- Advanced details are available under a collapsed **How it works & limits** section.
- Added an inline definition of test site / sandbox only where the example uses that concept.
- Added a separate fictional, non-technical practice fixture and `npm run demo:clear`.
- Shortened local template wording; no change to routing, authority or authorization logic.
- Added six view-contract tests and reran the existing behavior tests.
- Re-recorded actual UI operations and edited a 42-second stage film and 122-second Devpost film.
- Reduced the pitch to four core slides and four Q&A appendices.
- Prepared field-level Devpost text, a 3:2 thumbnail and four 3:2 gallery images from the supplied checklist.

## Not newly implemented here

Account management, contacts/projects, original notes, source-backed role routes, goals, deterministic planning, approval, tasks, deletion and signed Slack/Discord adapters come from earlier Threadline versions. This release does not claim they were newly created in the present hackathon window.

## No hidden functionality regression for presentation

Raw note text and dates are not rewritten for clarity. User confirmation is not pre-approved. A saved later message alone never replaces responsibility. Copies and saved drafts do not mean real contact occurred. Existing general workspace navigation and storage remain available. No new schema migration or paid-provider request is introduced.

## Meaning of the visual edit

The 42-second stage video replaces the earlier 57-second cut, not by running every screen unnaturally fast but by removing duplicate setup and using shorter labels. The 122-second submission video meets the supplied 2–3-minute requirement. It includes actual setup and a labeled close-up/replay; these do not represent a second independent execution. The edit is not a latency benchmark or novice-user comprehension study.
