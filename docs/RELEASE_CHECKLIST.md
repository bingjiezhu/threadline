# Warm Start release and rollout gates

The final report and `docs/VERIFICATION.md` record actual executed results. A checkbox here is an operator task, not a claim of success.

## Before relying on real private records

- [ ] Run supported Node and start an empty real account; protect the server and backups.
- [ ] Save your own authorized note, set the event date and explicitly confirm a responsibility.
- [ ] Create a goal, inspect the source and unknowns, approve selected tasks and confirm persistence after restart.
- [ ] Test source withdrawal, export and a full SQLite backup/recovery on a nonessential workspace.
- [ ] Understand that web core JSON restore does not restore the full Warm Start extension or chat bindings.

## Before a real model or platform claim

- [ ] Run the supplied explicit paid synthetic AI smoke command with your own authorized key. Check its real receipt and actual model.
- [ ] Evaluate output correctness, ambiguity, prompt injection, stale-source rejection, latency and provider spend. The daily request-count limit is not a dollar guarantee.
- [ ] Configure HTTPS, signing secrets, application IDs, the allowed Slack team and optional bot token; install with the correct scopes.
- [ ] Run real Slack and Discord linking, selected-message, private lookup, confirmation and disconnect checks. Inspect behavior in public channels and personal DMs.
- [ ] Keep upstream edit/deletion limitations explicit. Saving a message is not continuous synchronization.
- [ ] Verify native browser cookies, CSP, Origin checks, download, clipboard and extension behavior on the actual deployment.

## Before submission

- [ ] Organizer confirms deadline, prior public code eligibility, real event-window work and complete rubric.
- [ ] At most four actual accepted/RSVPed eligible teammates; required in-person presence arranged.
- [ ] Public source repository and 2–3-minute video are accessible without login. Preserve Apache-2.0 and disclose prior work.
- [ ] Fill real members/contributions/URLs in Devpost; do not present private archive hashes as public commit-time proof.
- [ ] Rehearse the two-minute live pitch plus three-minute Q&A separately from the longer video.
- [ ] Disclose local versus live AI/platform mode in both video and judge questions.

## Before paid public service

- [ ] Protected hosting, secrets, backups, monitoring, invitations and an operator support process.
- [ ] Actual privacy/subprocessor/retention terms consistent with the configured providers and customer permissions.
- [ ] Security and deployment review appropriate to real employee/business information.
- [ ] A real buyer agrees to pilot scope, price, cancellation and payment. No such payment was collected here.
